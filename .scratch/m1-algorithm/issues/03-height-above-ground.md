- [x] 姿態、位置照幀的 sim time 內插（線性；yaw 走最短角度），緩衝 1 秒（03 只內插 roll、pitch，yaw、位置、速度見 Comments）

## Comments

2026-11-26（使用者決定）：03 的前處理只做 `agl` 用得到的部分：§5 第 3～5 步，第 6 步只累加每格的有效點數和高度總和；整幀無效不會當掉。Moments 其他項、`h20`、2D 前綴和、第 7 步的無效像素落點留到 04，跟 `evaluate` 的測試一起寫。原因：03 唯一的輸出是 `agl`，其他部分在 03 看不到也測不到（spec 規定只測外部行為），先寫等於沒有測試的程式。

2026-11-26（實作，比照上面的決定）：內插在 03 只算 roll、pitch（`agl` 用得到的）；位置只要求前後兩筆夾得住這一幀才算能用。yaw 的最短角度內插和位置的值要到 06 的世界座標才看得到（M1 spec 的單元測試也寫「透過推薦點的世界座標觀察」），速度到 05 的 `moving`，跟各自的測試一起寫。幀時間比最後一筆姿態或位置新時，03 先不回傳高度；等 100 ms 的規則在 08。

2026-11-26（review AD2、AD-F1、AD-R3-1）：姿態的 roll 或 pitch 超過 ±(π + 1e-6)（含 NaN、inf）時整筆不收，跟沒收到一樣；只收過這種 → `no_px4`。很大的有限值內插時會溢位，所以用範圍檢查而不是只查有限值。多留 1e-6 是因為 MAVLink ATTITUDE 的欄位是 float，最接近 π 的 float 比 double 的 π 大約 9e-8，仍然是合法的角度。yaw 和位置的值在 03 沒用到，留給 06 一起檢查（06 的 Comments 有記）。

2026-11-26（使用者決定，review SP2）：深度幀的寬高跟 `camera.depth` 不同、或 `depth_mm` 長度不是 width × height 時，`on_depth` 保留丟 `std::invalid_argument`。尺寸錯是橋接程式或設定檔的錯；M2 讀 TCP 表頭時本來就要檢查 `payload_size`，對不上就斷線重連（dev_board_spec §4），例外只是最後一道保險。M2 呼叫 `on_depth` 要接住這個例外，決定怎麼處理（建議跟資料錯亂一樣斷線重連）。

2026-11-26（使用者決定，review ST-F2）：π 常數（`decision_core.cpp` 的 `kPi`、測試裡的字面值）先不抽成共用標頭。現在只有一個產品檔用到；06 檢查 yaw 時第二個產品檔也要用，那時再抽到 `src/core/` 的共用標頭。
