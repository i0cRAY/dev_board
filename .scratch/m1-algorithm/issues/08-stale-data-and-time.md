# 08: 資料過期、等內插、sim time 倒退

Status: ready-for-agent
Blocked by: 05, 07

**What to build:** 資料中斷、太慢、時間對不起來、Gazebo 重置時，高度、推薦、確認都照規則馬上回報，不會用舊資料回 `ok`，也不會一直等；恢復後自動正常。

**Seams:** 判斷核心

- [ ] 照 dev_board_spec §5「資料過期」和第 2 步：500 ms 過期、兩個都成立回 `no_depth`、內插最多等 100 ms、後一筆沒到但時間差 ≤ 100 ms 直接用、前後間距 > 100 ms 當成內插不到、比緩衝還早的幀丟掉、連續 500 ms 沒有能用的幀 → `no_px4`
- [ ] 等待內插的幀不會被新的幀取代，後面最多留最新的一幀：姿態固定晚 90 ms 時仍持續有結果
- [ ] 推薦用最新一幀；它在等就等它的結果；不能用就等下一個能用的，最多 500 ms；不退回更舊的幀
- [ ] 沒有深度、沒有 PX4、深度停 500 ms、PX4 停 500 ms、PX4 時間差 2 秒：分別 `no_depth`、`no_px4`、`no_depth`、`no_px4`、`no_px4`，推薦、確認、`agl` 都一致
- [ ] 確認收幀途中過期：馬上回，`counts` 是已收到的統計
- [ ] 過期原因不加入排除清單；資料恢復後推薦、確認、高度都恢復正常
- [ ] 深度幀或 PX4 時間比同一來源的上一筆小 1 秒以上：清空 PX4 緩衝、排除清單、上一次推薦的點，丟掉等待中的幀、還沒用掉的最新一幀、drop_check 已收的幀（1.5 秒期限不變）；小於 1 秒的亂序不清空
- [ ] 判 `hole` 被排除後 sim time 倒退，再按「推薦」不會回 `excluded`，也不會避開原來的點
- [ ] roadmap.md 的 M1 清單和完成標準照實際結果勾選
- [ ] `pc-debug`、`pc-release`、`h1v1`＋qemu 測試通過

## Comments

2026-11-28（05 留下的事）：
- 05 的 `on_position` 對 `vx`、`vy` 不是有限值的位置**整筆不收**（連 north、east、down 也不收）。加「PX4 最新一筆超過 500 ms → `no_px4`」時，這種位置不算「收到」：PX4 一直送壞的速度時會變成 `no_px4`，這是預期的，測試要照這個寫（05 review 的 SP1）。
- 05 的確認期限從收到請求的 `now` 算 1.5 秒，**每個事件**（姿態、位置、深度、確認請求、tick）一開始都會檢查，到了就在那個事件的結果回 `no_depth`。08 的「收幀途中過期馬上回」可以放在同一個地方。
- QA 觀察：PX4 比深度幀晚一點到時，現在那一幀直接丟掉（沒有等 100 ms），確認會一直收不滿、1.5 秒後回 `no_depth`。08 的「內插最多等 100 ms」做完才會正常。
